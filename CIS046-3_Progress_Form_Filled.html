Version Control
How did you develop your code (e.g., what features have ben added after first version)?
I developed the project using a GitHub repository following a structured feature-branch workflow. Starting from an initial project setup on the main branch, I developed the SQLite database authentication, the Banana API game engine, and the frontend interface on dedicated feature branches (feature/database-auth, feature/game-engine, and feature/frontend-ui), subsequently adding Google Sign-In, UI animations, and automated unit tests before merging all branches back into main.
Event Driven Architectures
What in your code triggers events (e.g., GUI, buttons, timeout …)?
Events are triggered by user GUI actions including submit button clicks, difficulty selections, Google login modal triggers, and pressing the Enter key on the answer input. In addition, a JavaScript setInterval countdown timer triggers periodic visual urgency ticks and dispatches an automatic timeout penalty event when time reaches zero, using asynchronous fetch() API calls to update the score, lives, and puzzle image without reloading the page.
Interoperability
Do you use the API https://marcconrad.com/uob/tomato/api.php? If no, where in your code do you demonstrate interoperability? What protocols do you use?
No, I integrated the official University of Bedfordshire Banana Game API (http://marcconrad.com/uob/banana/api.php?out=json) located in services/banana_service.py. The service communicates over the HTTP GET protocol using Python requests to retrieve and parse dynamic JSON puzzle payloads, and includes a 6-second timeout with an automated offline fallback mechanism to ensure gameplay continues seamlessly if the external server becomes unavailable.
Virtual Identity
How did you implement virtual identity in your code? (e.g., Passwords, Cookies, IP Numbers …)
Virtual identity is established through user registration and stored in an SQLite database, where passwords are cryptographically salted and hashed using Werkzeug rather than plaintext. Active player sessions are secured using signed HTTP-only cookies (session['user_id']), private routes like the dashboard and game arena are guarded by a @login_required decorator, and completed game scores are permanently linked to the user's account with optional Google Sign-In authentication.
Any other interesting features:
The architecture keeps correct puzzle solutions strictly on the Python backend so players cannot inspect frontend code to cheat. The game also enforces three distinct backend difficulty levels (Easy, Medium, Hard), delivers dynamic feedback through victory confetti and wrong-answer card shakes, and is verified by a 9-suite automated unit test framework in test_app.py.
